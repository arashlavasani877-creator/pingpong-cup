# جام پینگ‌پنگ — نسخه آنلاین دوحذفی

**این بسته آماده اتصال است، نه سایت مستقرشده.** تا وقتی پروژه Firebase ساخته نشود، چهار مقدار فایل `firebase-config.js` تکمیل نشود و Firestore Rules منتشر نشود، نتایج آنلاین کار نمی‌کنند.

## ایزوله‌سازی قطعی
- از همان حساب Google/Firebase استفاده می‌کنیم، اما **Create project > PingPong Cup** کاملاً جدید است؛ Firebase پروژه افراچوب را انتخاب نمی‌کنیم.
- GitHub: مخزن **جدید و مستقل** به اسم `pingpong-cup`. هیچ فایل و تنظیمی از `workshop-tracker` تغییر نمی‌کند.
- در GitHub Free، انتشار GitHub Pages نیازمند مخزن Public است. کد کلاینت و Firebase web config عمومی‌اند؛ کلید محرمانه، رمز عبور یا service account را داخل مخزن قرار ندهید.

## قدم‌های راه‌اندازی
1. با همان حسابی که برای افراچوب استفاده می‌کنید به https://console.firebase.google.com بروید و **Add project** را بزنید؛ نام `PingPong Cup`، پلن **Spark (free)**، Analytics اختیاری/خاموش. هرگز پروژه افراچوب را باز یا تغییر ندهید.
2. در پروژه تازه، Web app (آیکون `</>`) به اسم `pingpong-cup` ثبت کنید. از تنظیمات اپ، چهار مقدار `apiKey`، `authDomain`، `projectId`، `appId` را به فایل `firebase-config.js` منتقل کنید. Firebase Web API key معمولاً یک شناسه عمومی است، نه رمز مدیریتی.
3. **Build > Authentication > Sign-in method > Email/Password** را فعال کنید. در تب Users با **Add user** برای مدیر مسابقه یک حساب Email/Password بسازید. رمز را فقط در پنل خودتان وارد کنید؛ در کد یا چت قرار ندهید.
4. **Build > Firestore Database > Create database**، نسخه Standard و production mode را انتخاب کنید. از تب **Rules**، تمام متن `firestore.rules` را قرار داده و **Publish** کنید. از test mode یا قانون allow-all استفاده نکنید.
5. در GitHub با همان حساب موجود، مخزن **جدید** `pingpong-cup` از نوع **Public** بسازید (افراچوب را تغییر ندهید) و فایل‌های این بسته را در ریشه آپلود کنید. سپس **Settings > Pages > Deploy from a branch > main / (root) > Save**.
6. آدرس سایت: `https://YOUR-GITHUB-USERNAME.github.io/pingpong-cup/` (باید بعد از انتشار از GitHub دریافت شود). مدیر با ایمیل/رمز تعیین‌شده وارد می‌شود، ۲ تا ۶۴ بازیکن را وارد می‌کند، سپس دکمه **کپی لینک تماشاگران** را می‌زند. تماشاگران با گوشی و اینترنت مستقل همان لینک `?room=UID` را می‌بینند؛ ورود لازم نیست.
7. با دو مرورگر/گوشی تست کنید: ثبت نتیجه فقط از حساب مدیر ممکن، تماشاگر همان لحظه نتیجه را می‌بیند، Undo/فینال مجدد درست است، بدون VPN در ایران آزمایش نشده.

## امنیت و محدودیت‌ها
- Rules فقط به حساب صاحب UID مسابقه اجازه نوشتن می‌دهد؛ مشاهده تنها با داشتن لینک مربوط به UID ممکن است، اما چون `get` عمومی است، این **سیستم محرمانه با رمز تماشاگر نیست**؛ اسامی شخصی حساس وارد نکنید.
- مدیر ایمیل/رمز دارد؛ تماشاگران نیاز به ورود ندارند. ورود با سیم‌کارت/OTP در این نسخه ساخته نشده است؛ SMS Firebase ممکن است هزینه و محدودیت داشته باشد.
- یک سند Firestore برای یک مسابقه ذخیره می‌شود. با هر ثبت نتیجه یک سند به‌روزرسانی و در کلاینت‌های متصل دوباره خوانده می‌شود؛ برای مسابقات دوستانه کوچک طراحی شده.
- نسخه موجود از الگوریتم دوحذفی فایل اولیه استفاده می‌کند. فایل پشتیبان JSON نسخه ۲ آن قابل بازیابی است.
- اتصال اینترنت برای ثبت نیاز است. هنگام قطع اتصال، تماشاگر ممکن است اطلاعات کش را ببیند و مدیر نمی‌تواند نتیجه تازه ثبت کند.
- پلن Spark سقف دارد؛ عبور از سقف، قابلیت مربوط را محدود می‌کند. Firebase در بعضی شبکه‌های ایران ممکن است بدون VPN دسترس‌پذیر نباشد؛ تضمین نشده است.
- برای جلوگیری از پنهان شدن شکست‌های هم‌زمان، ثبت نتایج از transaction با بررسی revision استفاده می‌کند.

## برگشت و بکاپ
نسخه اصلی آفلاین داخل این بسته `original-offline.html` باقی مانده و مستقل قابل اجراست. در نسخه آنلاین، مدیر می‌تواند فایل JSON پشتیبان بگیرد. هیچ داده‌ای از افراچوب خوانده یا نوشته نمی‌شود.
